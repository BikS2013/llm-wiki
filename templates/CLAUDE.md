# LLM Wiki — schema

This directory is an **LLM-maintained wiki** built on Andrej Karpathy's LLM Wiki pattern. You (the LLM agent) write and maintain every page; the human curates sources, asks questions, and reads the results. Treat this file as the contract for how the wiki is structured and how to work on it. Evolve it together with the human when a convention stops serving the domain.

## Layout (three layers)

```
raw/            immutable source documents — READ ONLY, never edit or delete
raw/assets/     images and attachments belonging to sources
raw/<doc>.pdf.md, raw/<doc>.pptx.md, raw/<doc>.xlsx.md, raw/<img>.png.md, ...
                markdown conversions of PDF/DOCX/PPTX/XLSX/image originals (parser LLM; XLSX locally)
                (`llm-wiki parse` / `ingest`); frontmatter `original:` points at the untouched original
wiki/           the compiled knowledge base ({{FORMAT_NAME}} pages, `{{EXT}}`) — you own every file here
  index{{EXT}}{{PAD}}catalog of all pages, generated by `llm-wiki index` (do not hand-edit)
  log{{EXT}}{{PAD}}  append-only chronological record (`[YYYY-MM-DD] kind | title` entries)
  overview{{EXT}}{{PAD_OV}}optional top-level synthesis of the whole corpus{{EXTRA_LAYOUT}}
  sources/      one summary page per ingested raw source
  entities/     people, organisations, products, places, projects, tools
  concepts/     ideas, methods, themes, recurring questions
  syntheses/    filed answers, comparisons, analyses, evolving theses
  lint/         dated health-check reports
.llm-wiki/      tool state (search index, embeddings, ingest ledger) — do not edit
CLAUDE.md       this schema (AGENTS.md is a copy for other agents)
```

## Page format

{{PAGE_FORMAT}}

Conventions:
- File names are lowercase kebab-case slugs of the title: `entities/ada-lovelace{{EXT}}`.
{{LINK_CONVENTION}}
- Cite the raw source for every non-obvious claim: `([[sources/paper-title]])` or a `Sources` section at the bottom. Facts must be traceable to `raw/`.
- When a source page comes from a converted document or image (PDF, DOCX, PPTX, XLSX, PNG, JPEG, ...), its metadata carries `original: raw/<doc>.pdf` and the page links the original; keep that link when you edit the page.
- Keep pages atomic: one entity or concept per page. Prefer updating an existing page over creating a near-duplicate; check `wiki/index{{EXT}}` and `llm-wiki search` first.
- Flag contradictions explicitly with a {{CONTRADICTION}} callout naming both sources; never silently overwrite an older claim — say what changed and why.
- Set `updated` whenever you touch a page and keep `sources` accurate.

## Operations

**Ingest** (`llm-wiki ingest raw/<file>`, or do it yourself): read the source in full, discuss key takeaways with the human if they are present, then (1) write `sources/<slug>{{EXT}}` with a faithful summary, key claims, and notable quotes; (2) create or update the entity and concept pages the source touches — typically 5–15 pages; (3) update `overview{{EXT}}` if the big picture shifted; (4) run `llm-wiki index` to regenerate `index{{EXT}}`; (5) append a log entry (`ingest | <title>`) listing pages touched — `wiki_append_log` over MCP does it in either format.

**Query** (`llm-wiki query "<question>"`, or do it yourself): read `index{{EXT}}` first, then `llm-wiki search "<terms>"` to locate candidate pages, read them, and answer with citations to the pages used. If the answer is valuable (a comparison, an analysis, a connection), file it as `syntheses/<slug>{{EXT}}` and log `query | <question>`.

**Lint** (`llm-wiki lint`, add `--llm` for semantic checks): look for contradictions between pages, stale claims superseded by newer sources, orphan pages, important concepts mentioned but lacking a page, missing cross-references, and data gaps worth a web search. Write the findings to `lint/<date>{{EXT}}`, fix what is safe to fix, and log `lint | ...`.

## Tools

The `llm-wiki` CLI operates on this directory. Name it with `--wiki <name>` when it is registered (see `llm-wiki wikis`), or pass `--root <this directory>`:

| Command | Purpose |
|---|---|
| `llm-wiki search "<query>" [--mode bm25\|vector\|hybrid] [--layer wiki\|raw\|all]` | Full-text / semantic search over pages (and optionally raw sources) |
| `llm-wiki index [--raw] [--embed]` | Regenerate `index{{EXT}}` and the search index (+ embeddings){{INDEX_EXTRA}} |
| `llm-wiki ingest <file>` | LLM-driven ingest of a raw source into the wiki (PDF/DOCX/PPTX/images are converted first by the parser LLM, XLSX locally) |
| `llm-wiki parse <file.pdf\|file.docx>` | Convert an original to `raw/<file>.md` with the parser LLM, without ingesting |
| `llm-wiki query "<question>" [--file]` | LLM-driven answer with citations, optionally filed as a synthesis page |
| `llm-wiki lint [--llm] [--fix]` | Structural (and semantic) health check |
| `llm-wiki log --last 5` | Recent log entries |
| `llm-wiki mcp` | Expose the above as MCP tools (`wiki_search`, `wiki_read_page`, ...) |

After you write or edit pages by hand, run `llm-wiki index` so `index{{EXT}}` and the search index stay current.

## Working style

- The human decides what to source and what to ask; you do the bookkeeping: summarising, cross-referencing, filing, keeping the index and log current.
- Never modify anything under `raw/`.
- When unsure whether two things are the same entity, keep them separate and add a `> **Possible duplicate of [[...]]**` note for the next lint pass.
- Prefer many small, well-linked pages over a few long ones.
